# NSE Intraday + Swing-Trading Project — Evidence-Based Audit (2026-07-25)

Auditor role: quant researcher / NSE market-data engineer / Python dev / system auditor.
Every finding below was checked against the actual files and the on-disk data lake, not
assumed from the code reading alone. Labels used: **VERIFIED** (I ran it / read the bytes),
**DOCUMENTED** (provider/dataset states it, not independently re-verified here),
**UNVERIFIED CLAIM**, **INFERRED**, **MISSING**.

---

## A. Executive summary

The `research/intraday/` package is **honest, well-structured research software** and is the
strongest part of this project. It explicitly refuses to claim 2010→present all-NSE 1-minute
coverage, records provenance per row, and separates verified vs documented coverage. The
recently-updated backend (`swing_trading.py`) now contains **pure, testable
`validate_recommendation()` and `determine_fill()` functions** that already implement most of
the swing-recommendation and paper-fill rules this audit was asked to check.

It is **not** production-ready as a 2010→present intraday backtesting system, and cannot be,
because the data does not exist for free. What exists is: a verified index-only 1-minute lake
(NIFTY 2008-2020, BANKNIFTY 2010-2020), a recent Yahoo equity sample, and a set of adapters for
account-bound broker APIs (Upstox 2022+, Dhan trailing-5y) that have **not yet been run with
real credentials**.

**Confirmed blocking issues:**
1. **CRITICAL — the on-disk canonical lake contains 14,250 exact-duplicate rows** in the NIFTY
   2016-07 partition (7,125 timestamps doubled), directly contradicting `VERIFIED_COVERAGE.md`'s
   claim of "canonical duplicate keys after upsert: 0". VERIFIED.
2. **HIGH — the lake on disk was written by an older code path** (hash-suffixed filenames) that the
   current `write_partitioned` no longer produces, so the current code is **not idempotent against
   the existing lake** and `validate` would now fail (exit 2) on those duplicates. VERIFIED.
3. **HIGH — no survivorship-free point-in-time universe exists**; the daily research file and the
   intraday lake are both current-symbol / index-only. Known and documented, not yet solved.
4. **MEDIUM — volume is absent for the entire index lake** (VERIFIED: all NIFTY/BANKNIFTY rows have
   NaN volume), so any volume-dependent signal on the historical lake is invalid.

No fabricated data was found. No look-ahead was found in the daily backtest. The intraday
"timeframes from 2010" shown in the main notebook are **derived from a 7-day recent Yahoo window**,
not from 2010 — the notebook labels this correctly but a reader could still be misled (see G/I).

## B. What the project currently does

- **`research/intraday/`** — an acquisition + audit "lake" layer:
  - `source_catalog.json`: 11 documented sources with access type, windows, intervals, priority,
    and coverage-confidence labels.
  - `providers.py`: adapters for Yahoo (recent), Upstox v3, Dhan v2, Alpha Vantage, Kaggle
    index CSVs, generic CSV.
  - `schema.py`: canonical 16-column schema, normalization, quality flags, partitioned Parquet
    writer with sidecar manifests + SHA-256 digests.
  - `pipeline.py`: CLI for `catalog`, `plan`, ingest, `validate`, `merge` (priority-based).
  - `audit_lake.py`: coverage / session-gap / conflict reports.
  - `test_pipeline.py`: 6 unit tests (all VERIFIED passing).
- **Two notebooks**: a general multi-timeframe research notebook (daily 2010→present + recent
  intraday for one stock + all-NSE daily screen + daily backtest), and a focused notebook that
  builds all 9 timeframes for BANKNIFTY for the first real trading week of 2010.
- **Backend swing engine** (`swing_trading.py`): v4 selection/exit, plus new pure functions
  `validate_recommendation()` / `determine_fill()` and `NON_ACTIONABLE_STATUSES` used by the
  scanner, the "14-Day Desk", and the paper-trading engine.

## E. File-by-file findings

### E1. `schema.py` — mostly production-quality
- Purpose: canonical schema, normalize, quality flags, partitioned write, digest, read.
- **[HIGH] Idempotency/atomicity mismatch with on-disk lake.** `write_partitioned` (L206) writes
  `{file_stem}.parquet` (no hash), but the lake on disk has `…-<hash>.parquet` names → the current
  code will **write a second file** beside the old one instead of upserting into it. Evidence: disk
  files `banknifty-community-70c903f572bb59c2.parquet`; code produces `banknifty-community.parquet`.
  Consequence: re-ingestion duplicates rows across two files; dedup (which is per-file on read of the
  *same* path) won't catch it. VERIFIED (filenames + duplicate rows).
- **[MEDIUM] `.tmp.parquet` + `.replace()` is atomic per file, but a multi-partition write is not
  transactional** — an interruption leaves a partial set with a valid-looking manifest each. Resume
  is "safe per partition" only.
- **[MEDIUM] Session flag is a static 09:00-15:29 window** (L135). Documented as intentional, but it
  cannot distinguish the 09:00 (pre-18-Oct-2010) vs 09:15 regimes, and flags legitimate special
  (muhurat) sessions as `outside_regular_session`. It only flags (doesn't drop), so acceptable, but
  the flag is noisy and not date-aware.
- **[LOW] `missing_volume` counts NaN volume as a flag but `QualitySummary.clean` ignores it** (L50-53)
  — correct by design (volume-optional), just note it.
- **[LOW] `add_quality_flags` recomputes flags every read** (O(n)); fine at current scale, wasteful at
  billions of rows.

### E2. `providers.py`
- **[MEDIUM] Alpha Vantage timestamps are localized to Asia/Kolkata unconditionally** (via
  `normalize_candles` default tz). AV intraday returns exchange-local time; for a non-NSE symbol this
  mislabels tz. Low real impact because NSE AV coverage is unverified/unused, but latent.
- **[LOW] No retry / rate-limit / backoff** on any HTTP adapter (Upstox/Dhan/AV). Dhan's documented
  90-day-per-request and rate caps are not enforced in code — the README tells the human to chunk
  manually. A batch backfill will hit limits.
- **[LOW] Upstox/Dhan responses are trusted structurally** — a changed schema or an error body with
  HTTP 200 would produce an empty/garbled frame. AV has a JSON-error guard (good); the brokers don't.
- **[LOW] `import_kaggle_nifty_bank_file` hardcodes `format="%Y%m%d %H:%M"`** — correct for this
  dataset, but silently coerces anything else to NaT (dropped). Acceptable for a named importer.
- Credentials read from env vars only — **no secrets in code. GOOD.**

### E3. `pipeline.py`
- **[MEDIUM] `merge_by_priority` dedups on `(symbol, timestamp_utc)` and keeps highest priority**
  (correct), but **`conflicts` is written with all overlapping rows including the winner**, and there
  is no record of *which* value won vs lost per field — provenance of the resolution isn't captured
  beyond "here are the rows". Adequate for research, not for audit-grade reconciliation.
- **[LOW] `coverage_plan` scope matching** uses substring logic (`"indice" in scope`,
  `"stock" in scope`) that is fragile (e.g. `instrument_scope: "indices_only"` contains `"indice"`
  → matches `index`; fine, but brittle if a new scope string is added).
- **[LOW] `command_validate` reads the entire lake into RAM** (`read_partitions(rglob('*.parquet'))`).
  Fine for 1.7M rows; breaks the "do not load the whole 1-minute universe into RAM" rule at scale.
- **[LOW] Rolling-window resolution is anchored to `--end`** (documented) — good for reproducibility,
  but means `plan` for a *past* end date will compute a past rolling window, which is usually intended
  but can surprise.

### E4. `audit_lake.py`
- Solid. Per-source/symbol/month coverage, per-session gap counts, conflict listing. **[LOW]** the
  per-session Python loop (`groupby(... _date).apply`-style) is slow at scale; vectorize later.
- **[MEDIUM] It will currently report the 7,125 NIFTY duplicates as conflicts/flagged** — which is
  correct behavior and is exactly how the dup bug surfaces.

### E5. `source_catalog.json`
- Well-labelled with `coverage_confidence`. **[LOW]** `kaggle_nifty100_2015_2022` lists intervals
  `["5m"]` with a note that the title says 1m but samples are 5m — good honesty; make sure downstream
  never assumes 1m from it.

### E6. `VERIFIED_COVERAGE.md`
- Excellent and mostly accurate. **[HIGH] One false statement**: "canonical duplicate keys after
  upsert: 0" — the live lake has 7,125. Must be corrected or the lake must be rebuilt so it becomes
  true.

### E7. `README.md`
- Accurate, reproducible commands, correct historical session warning. Production-quality docs.

### E8. `nse_multi_timeframe_research.ipynb`
- **[MEDIUM] Intraday timeframes are built from a 7-day Yahoo window but presented in the same
  "multi-timeframe" table as the 2010 daily series.** The markdown is honest, but `coverage_df`
  juxtaposes `1m…5h` (last 7 days) next to `1d` (2010→now) — a reader can misread it as "2010 intraday".
- **[MEDIUM] Cell 7 uses a fixed `offset='9h15min'`** for every intraday resample. Correct for
  recent Yahoo data, wrong if ever fed pre-Oct-2010 data (should be 09:00). Not a live bug (no old
  intraday flows through it), but a latent one.
- **[MEDIUM] Cell 10 "latest multi-timeframe status" uses `.iloc[-1]`** which may be an *incomplete
  forming bar* → look-ahead-ish for a live status read. Harmless for research display, wrong if used
  as a signal.
- Daily backtest (Cell 11): see section I — it is actually careful.

### E9. `nse_one_week_2010_multiframe.ipynb`
- **Best-practice example.** Correctly uses BANKNIFTY (not HDFC) because no open 2010 equity 1-min
  exists; uses the historical **09:00** anchor; retains and labels partial bars; asserts OHLC validity;

  dayfirst=True`, which is riskier than the explicit format in `providers.py`; contained because it
  only selects one known week.

## G. Swing-recommendation logic findings

The backend **already implements** the required classifications in
`swing_trading.validate_recommendation()` (L55-127). Credit where due:

- ✅ `current_price >= target` → **TARGET_ALREADY_REACHED** (L95-98). The exact ₹100/₹130 example
  in the brief is handled correctly.
- ✅ Minimum remaining reward gate: `min_remaining_upside_pct` (L99-103, default 2%).
- ✅ READY_TO_BUY / WAIT_FOR_ENTRY / NEAR_BUY_ZONE / MISSED_ENTRY / INVALID all present with the
  intended semantics; NEAR vs MISSED split by `near_zone_tolerance_pct` and `max_entry_price`.
- ✅ INVALID guards: stop must be below entry, target above entry, entry inside its own zone.

**Findings / gaps:**
- **[HIGH] The min-upside + TARGET_ALREADY_REACHED checks only fire when `target is not None`
  (L94).** Production v4 sets `target = None` (no take-profit). So for real v4 picks, a stock that has
  already run far past any reasonable level can still be shown as READY_TO_BUY / NEAR_BUY_ZONE — the
  "already played out" guard is silently inert for the actual production configuration. Evidence:
  v4 exit config sets `target1/2/3 = None`; `validate_recommendation` skips the whole target block
  when target is None. **Fix:** when target is None, gate freshness on a proxy (e.g. distance from the
  signal's reference/close, or an ATR-based ceiling), or require an explicit `reference_target` for
  validation even if no TP is traded.
- **[MEDIUM] STALE (signal older than its allowed lifetime) is not part of this pure function.**
  `NON_ACTIONABLE_STATUSES` includes `DATA_STALE`, but that is price-freshness, not signal-age.
  Signal-age expiry exists only as `pending_entry_max_days` in the paper watch loop, not in
  recommendation display. **Fix:** add a `signal_age_days` / `max_signal_age` parameter and a
  `STALE` status in `validate_recommendation`.
- **[LOW] Naming:** the docstring lists 6 statuses but omits `NEAR_BUY_ZONE` vs the frozenset — keep
  the enum in one place to avoid drift.

## H. Paper-trading logic findings

`determine_fill()` (L130-160) is a **pure, no-lookahead fill decision** and is well-designed:

- ✅ Never fills above `min(buy_zone_high, max_entry_price)` — a gap over the whole zone returns
  **MISSED_ENTRY**, not a fill at the stale suggested price (exactly the required rule).
- ✅ Applies slippage to a buy (fills worse than the print).
- ✅ Returns DATA_STALE when no fresh price; WAIT_FOR_ENTRY when below the zone (→ pending).
- ✅ Docstring makes the caller responsible for passing only prices observed **at/after** the signal
  timestamp (no backdating).

**Findings / gaps:**
- **[HIGH] The pure function is correct, but the caller (`paper_auto_check`, ~L1870-1923) must be
  proven to (a) only pass post-signal observed prices and (b) store signal-time/order-time/fill-time
  separately.** From the grep, statuses are written back and DATA_STALE is set on missing price, but I
  did **not** find explicit persistence of `fill_time` + `source_candle` + `order_time` as distinct
  audited fields in the paths I read. **Action:** verify/extend the paper record to store
  signal_time, order_time, fill_time, fill_price, fill_reason, source (per the brief). Labeled
  **INFERRED-INCOMPLETE**, not confirmed-broken.
- **[MEDIUM] Same-candle stop-and-target ordering** is not addressed for exits because v4 has no
  take-profit (target None) — so in production the conflict can't occur. But the **research
  notebook** backtest (Cell 11) does define both and resolves it "stop first" (documented). The two
  code paths use different exit assumptions; unify the documented rule.
- **[MEDIUM] Fill uses `observed_price` (a single print), not "next tradable price".** For daily
  cadence the caller passes a fresh LTP; there is no intrabar model (the project has no intraday
  equity data to support one). Acceptable given data reality, but the fill is an LTP-touch model, not
  a next-bar-open model — state this in reports.
- **[LOW] Slippage is one-directional (buys only shown).** Confirm the sell/exit side also applies
  adverse slippage in the P&L path.

## I. Backtesting and bias findings

- **Look-ahead (daily backtest, notebook Cell 11): NOT PRESENT.** Signal on completed candle `i-1`,
  entry at `open` of candle `i`, adverse slippage, conservative "stop-before-target" same-candle rule,
  no overlapping positions. This is careful and correct. VERIFIED by reading.
- **Survivorship bias: PRESENT** across the whole project (current-symbol universe / index-only lake).
  HIGH. This is the single biggest validity threat and is openly documented, not hidden.
- **Costs:** daily backtest applies round-trip cost (20 bps) + 5 bps/side slippage — reasonable and
  configurable. Indian statutory charges (STT/GST/stamp/exchange/SEBI) are **not itemized** (folded
  into a flat bps). MEDIUM for realism.
- **Incomplete candles:** notebook resampler labels partial bars via `source_minutes` and the 5h bar
  is correctly split into 300m + a labelled 75-minute partial. GOOD.
- **Gap handling:** the gap-over-zone → MISSED_ENTRY rule is correct; extreme gap-up entries are
  known-losers per the v4 study and are capped by `max_entry_price`.
- **Overstated performance risk:** any headline number on the current data would be **optimistically
  biased** (survivorship + index-only history + no delisted names). Must be caveated in every report.

**5-hour bar (the brief's specific question):** NSE regular session = 375 minutes (09:15-15:30).
Anchored at the open, the **first 5h bar spans 09:15-14:15 (300 min, complete); the second spans
14:15-15:30 = only 75 minutes (partial).** The correct handling — implemented in the one-week
notebook — is: resample per session with `origin=start_of_session`, keep the 75-min remainder as a
**labelled partial bar** (`source_minutes=75 < 300`), and **never merge it with the next day's first
segment**. For pre-18-Oct-2010 data the anchor is **09:00** (session 09:00-15:30 = 390 min → 300 +
90 partial). The main notebook hard-codes 09:15 and would mis-anchor 2010 data (latent, section E8).

## K. Security and operational findings

- **GOOD:** all broker/API credentials come from environment variables (`UPSTOX_ACCESS_TOKEN`,
  `DHAN_ACCESS_TOKEN`, `ALPHAVANTAGE_API_KEY`, etc.). No secrets in code or catalog.
- **[MEDIUM] `source_file` stores absolute local paths** (e.g. `%USERPROFILE%\.cache\kagglehub\…`)

- **[LOW] No `.env` wiring** in the intraday package (env vars must be exported manually) — fine, just

  Derived Parquet in the lake inherits that restriction — do not redistribute; the README notes it.
- **[LOW] No manifest verification step** — digests are written but nothing re-checks them on read.

## L. Recommended architecture (incremental, not a rewrite)

1. **Keep** the canonical schema, catalog, provider adapters, and partition layout — they are sound.
2. **Fix the write/dedup identity** (F1/F2): one deterministic filename per partition; upsert reads
   the existing partition, concatenates, dedups on `(source, symbol, timestamp_utc)`, atomic-replaces;
   add a one-time `migrate`/`dedup` command to repair the current lake.
3. **Add a DuckDB scan layer** for `validate`/`audit`/`merge` so nothing loads the whole lake into RAM.
4. **Add a point-in-time security master** (separate table): `instrument_id (ISIN-based)`, symbol
   history with valid-from/valid-to, listing/delisting dates, corporate actions, index-membership
   history. Join backtests to *point-in-time* membership, never to today's list.
5. **Tiered, labelled datasets** (never blended): Tier A daily 2010→now (rebuilt survivorship-free);
   Tier B intraday = whatever Upstox/Dhan actually deliver once tokens are supplied (verify first);
   Tier C recent 1-min for slippage studies. Each carries a coverage manifest.
6. **Feature/label layer** enforces: no volume features on the volume-less index lake; as-of
   (backward) joins for multi-timeframe; date-aware session calendar (09:00 vs 09:15).
7. **Reports** always separate verified / documented / unverified, and print costs + universe version.

## N. Test plan (proposed additions to `test_pipeline.py`)

Existing (VERIFIED passing): normalize+quality, invalid-OHLC flag, partition round-trip, upsert
idempotency (fresh dir), priority merge, 2010 no-free-full-coverage plan.

Add:
1. **Duplicate ingestion against a pre-seeded partition** (regression for F2) — ingest same rows into
   an existing hash-named partition; assert final row count unchanged and one canonical file.
2. **Interrupted resumption** — simulate a `.tmp.parquet` left behind; assert recovery.
3. **Timezone conversion** — naive IST vs tz-aware UTC input both land on identical `timestamp_utc`.
4. **Historical session change** — a 2010-01-04 09:00 bar is *not* flagged outside-session under a
   date-aware calendar; an 09:05 bar in 2020 *is* (pre-open).
5. **Incomplete candles** — 5h resample yields a 300-min bar + a labelled 75-min partial; partial is
   excludable.
6. **No-look-ahead resampling** — a left-labelled bar's window never includes a future minute; as-of
   join of 5m onto 1m never sees an unclosed 5m bar.
7. **Conflicting providers** — same ts, different close, different source → higher priority wins,
   both recorded in conflicts.
8. **Volume-absent guard** — feature layer refuses volume signals when `volume` is all-NaN.
9. **Recommendation:** target-reached (₹130 example) → TARGET_ALREADY_REACHED; **target=None** path
   still classifiable (regression for G-HIGH); min-upside boundary; NEAR vs MISSED boundary at
   `max_entry_price`.
10. **Paper fill:** gap-over-zone → MISSED_ENTRY (no fill); below-zone → pending; target-before-entry
    → no profit; pending expiry → EXPIRED; no backdating (fill_time ≥ order_time ≥ signal_time);
    same-candle stop+target → documented rule.
11. **API failures** — empty candles, HTTP error, AV JSON error body, rate-limit response → adapter
    returns empty/ raises cleanly, never a garbled frame.

## P. Final verdict

**The intraday package is honest, careful, and the right foundation — but it is a partial,
index-heavy, survivorship-biased research lake, not a 2010→present all-NSE intraday system, and it
currently ships one false coverage claim and a real duplicate-row defect in the lake on disk.**

- As **research software**: B+/A- once F1/F2 and the `VERIFIED_COVERAGE.md` line are fixed.
- As a **2010→present intraday backtester**: **not achievable on free data**; the project already
  says so, and the evidence confirms it.
- **Do not** promote anything to production on the current data. The daily backtest logic and the
  new recommendation/paper-fill functions are sound enough to keep building on; fix the confirmed
  defects, add the point-in-time universe, and treat every historical result as
  survivorship-caveated until a licensed/authoritative source fills the gaps.

*Treat all of the above as research findings, not financial advice.*
